Developer orientation

Follow responsibilities, then call paths

The codebase has 27 Java files and no application framework. Start from process entry points, then follow the small interfaces at subsystem boundaries.

Startup and discovery

PeerApplication→AppConfig→PeerRuntime→PeerServer→TrackerClient

Configuration loading occurs off the EDT; the window is constructed and displayed in a disabled Starting state while a SwingWorker starts the runtime and tracker registration in the background. Refresh uses another SwingWorker to update the peer list on the event thread. Tracker client methods serialize requests with a request lock while permitting non-blocking detached close.

Transfer call paths

Send: MainFrame → PeerRuntime → TransferManager → executor → FileSender.run.

Receive: PeerServer.acceptLoop → TransferManager → executor → FileReceiver.run → optional prompt.

UI: transfers emit TransferUpdate; MainFrame marshals it onto Swing’s event thread. Rows are keyed by transfer ID.

Resource ownership

  • Tracker handlers and receivers close accepted sockets with try-with-resources.
  • FileSender owns its outgoing socket and source file handle.
  • FileReceiver owns the destination handle; partial files intentionally survive many failures.
  • PeerRuntime.close closes tracker, peer listener, then transfer executor.
  • Transfer exceptions become UI messages; there is no structured persistent error log.

Invariants

  • Never send file bytes through the tracker.
  • Treat offered names as untrusted base names.
  • Validate session, index, offset, length, hash, and duplicate state before writing.
  • Keep incomplete content temporary until complete verification.
  • Keep session IDs separate from stable content IDs.
  • Update every affected handbook page and the changelog with each change.

Test placement and reusable runtime seams

Tests are organized into deterministic unit checks (*Test.java via Surefire) and real-socket localhost integration tests (*IT.java via Failsafe):

  • common: protocol framing roundtrip, truncation, version/magic boundary tests in FrameIOTest.
  • tracker-server: real socket registration, peer listing, and disconnect lifecycle in TrackerServerIT.
  • peer-app: end-to-end direct file transfer and rejection in TransferFlowIT, using IncomingFilePrompt and TransferListener as reusable headless seams without constructing Swing windows. Test-scoped dependency on tracker-server allows multi-peer integration without polluting production dependencies.

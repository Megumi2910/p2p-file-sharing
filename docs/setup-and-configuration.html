Build and operate

Prepare the tracker and two peers

The intended classroom topology places the tracker on Windows and one Swing peer on each Ubuntu Desktop VM. All three machines must share a reachable private or host-only network.

Prerequisites

  • JDK 21 on the build machine and Java 21 runtime on every machine running a JAR.
  • Maven 3.9 or newer on the build machine.
  • Ubuntu Desktop or another graphical Linux session for Swing peers.
  • A host-only/private adapter permitting VM → host and VM → VM traffic.
java -version
mvn -version

Verified local evidence: JDK 21 and Maven 3.9.16 clean verify passes all 74 unit and integration tests, producing verified executable shaded JARs.

Build from the repository root

mvn clean verify

This runs the deterministic local behavioral gate across all three modules (including JUnit unit and integration tests) and produces the shaded executable JARs. To compile and package without running the integration test gate, run mvn clean package. The parent reactor produces:

tracker-server/target/tracker-server.jar
peer-app/target/peer-app.jar

Continuous Integration: A GitHub Actions workflow (.github/workflows/ci.yml) automatically executes mvn -B -ntp clean verify on both ubuntu-latest and windows-latest matrix runners on every push and pull request to main, enforcing headless test verification across platforms.

Start the tracker on Windows

java -jar .\tracker-server\target\tracker-server.jar 5000

Port 5000 is the default. The server binds on all local interfaces through new ServerSocket(port). If Windows Firewall prompts, allow Java on the relevant private network. The provided run-tracker-windows.bat assumes it is launched from the repository root because its JAR path is relative.

Expected log:

[TRACKER] Listening on 0.0.0.0:5000

Configure each peer

Copy peer-app/src/main/resources/peer.properties.example beside the peer JAR as peer.properties. Relative download paths resolve from the process working directory, not from the properties file’s directory.

PropertyRequired/defaultMeaning and validation
peer.idRequiredUnique identifier (≤ 255 chars, no ISO control chars).
peer.nameRequiredHuman label (≤ 255 chars, no ISO control chars; Unicode preserved).
peer.portDefault 6001Listening TCP port for P2P transfers (validated 1..65535).
tracker.hostDefault 127.0.0.1Tracker host IP address (nonblank).
tracker.portDefault 5000Tracker TCP port (validated 1..65535).
download.dirDefault downloadsDownload directory. Verified existent/created and writable on startup.
shared.dirDefault sharedShared files directory. Indexed on startup and published to tracker catalogue.
chunk.size.bytesDefault 1048576Chunk size in bytes (1..8,388,608 bytes).
transfer.autoAcceptDefault falseStrict boolean (true/false). Rejects invalid text.
tracker.read.timeout.msDefault 15000Read inactivity timeout for tracker registration/list responses.
transfer.read.timeout.msDefault 15000Read inactivity timeout for incoming offers, chunk data, and ACKs.
transfer.prompt.timeout.msDefault 120000Receiver decision budget (1..MAX_INT ms). Must be < offer response timeout.
transfer.offer.response.timeout.msDefault 135000Sender wait for accept/reject. Must strictly exceed prompt timeout.
transfer.verify.timeout.msDefault 300000Sender wait for whole-file verification result.
transfer.max.concurrentDefault 4Maximum concurrent transfer tasks (1..64). Bounded thread pool with SynchronousQueue.

Verify the network before Java

On Windows, use ipconfig to identify the host-only adapter. On both VMs:

ip a
ping 192.168.56.1

After Bob is listening, test his port from Alice:

nc -vz <BOB_VM_IP> 6002

Also verify that neither peer port is already in use and that VM firewalls permit inbound TCP. Different VMs may technically use the same port, but distinct ports make logs and demonstrations clearer.

Start peers

java -jar peer-app.jar peer.properties

The provided run-peer-linux.sh runs exactly that command and therefore expects both files in the current directory. Startup first binds the peer port, then connects and registers with the tracker. Expected logs include:

[PEER] Listening for P2P transfers on 0.0.0.0:6001
[PEER] Tracker sees this peer as 192.168.56.101:6001
Exception-safe rollback (F-07): If peer binding succeeds but tracker registration fails, automatic rollback immediately closes all acquired resources, allowing the local listening port to be rebound without leaving dangling background threads.

Stop and restart

Closing the Swing window exits the process; shutdown hooks attempt to disconnect and close runtime services. Stop peers before the tracker for clean unregistration. After an abnormal stop, wait for the operating system to release ports and remove unwanted .part files only after confirming no transfer process is still using them.

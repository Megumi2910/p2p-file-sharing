Mandatory project policy

Documentation changes with the project

Every repository change, however small, must update all affected documentation in the same task. Documentation is part of the definition of done.

Workflow for every change

  1. Trace impact before editing. Identify observable behavior, protocol, configuration, architecture, operations, failure modes, examples, diagrams, tests, and status labels affected.
  2. Choose the owning page. Correct the detailed explanation at its single source. Link from other pages instead of copying large sections.
  3. Update all consumers. Keep navigation, worked examples, teaching simulations, troubleshooting steps, and README summaries consistent.
  4. Record the change. Add one changelog entry per completed change set, including documentation-only and tiny changes.
  5. Verify. Check facts against active source, run proportionate code checks, validate local links/assets, and exercise affected HTML interactions.

Writing and evidence rules

  • Explain why and observable behavior before implementation names.
  • Label active, planned, known-limit, and unverified claims accurately.
  • Use source and fresh runtime evidence; never turn a proposal into present tense.
  • Include normal and failure paths for important workflows.
  • Keep examples executable or label them as illustrative.
  • Do not paste whole source files; use short excerpts and meaningful anchors.
  • Keep HTML usable offline, responsive, keyboard-readable, printable, and understandable without JavaScript.

Adding a page

Add a page only when it serves a distinct reader job and has enough depth to avoid becoming a thin fragment. Add it to every sidebar and connect previous/next navigation. If its topic already has an owner, expand that page instead.

Material plans: The single active foundation authority is Project foundation and execution plan. Future approved material plans belong under docs/plans/ and must be linked to the sidebar and previous/next chains.

Verification checklist

  • Every local href, stylesheet, script, image, and source link resolves.
  • Every page has one descriptive title/H1, language, charset, viewport, and current navigation marker.
  • Affected demos produce correct boundary results and useful no-script fallback text.
  • Desktop and narrow layouts do not hide content; wide tables remain reachable.
  • Commands and paths match manifests, scripts, and active source.
  • The changelog states why, behavior impact, compatibility/config impact, checks, and doc links.
  • No secrets, private addresses presented as universal values, unsupported claims, or stale TODO prose.
No recursive churn: editing documentation satisfies the documentation part of that change. It does not require a second changelog entry merely to describe the first changelog edit.

Source of enforcement

The repository-root AGENTS.md carries the concise rule for future coding agents. This page owns the detailed procedure. If the policy changes, update both without duplicating this full checklist in the agent file.

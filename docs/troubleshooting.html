Symptom-first diagnosis

Find which boundary failed

Check process, route, port, and protocol in that order. Preserve console output and the exact UI message before restarting; the application has no persistent diagnostic history.

Fast network ladder

  1. Can each VM see its own IP with ip a?
  2. Can each VM ping the Windows host-only IP?
  3. Is the tracker listening on Windows port 5000?
  4. Does each peer log a tracker-observed address?
  5. Can Alice open Bob’s peer port with netcat?
  6. Does refresh cause a tracker request and response?

Partial files

A .part file means publication did not finish. The application cannot resume it and does not automatically delete it. Before deletion, ensure no peer process is using it. Its allocated length may equal the advertised final size even when many ranges were never received because setLength preallocates it.

Truthful progress reporting (F-05): Confirmed byte counts represent matched acknowledgements on the sender and unique verified writes on the receiver. On failure, confirmed bytes are never reset to zero. Progress calculation ensures that completed empty files show 100%, and uncompleted empty files show 0%, with no integer overflow or inflated percentages.

Do not infer integrity from size or 100% progress. Only a successful whole-file SHA-256 and final rename prove the current receiver accepted the completed content.

Project foundation and execution plan

This is the sole approved execution authority for stabilizing the Java 21 / Maven P2P file sharing baseline before expanding features. It establishes architecture boundaries, sequential transfer state invariants, safe publication, bounded admissions and lifecycle teardown, followed by local and VM proof tiers.

Single approved authority under docs/plans/. Supersedes root-level planning markdown while preserving existing topic page paths until post-proof cutover.

Boundary

Private LAN scope

Trusted/controlled private-network operation. R-008 plaintext exposure remains unresolved; checksums are not authentication.

Context and architecture to preserve

  1. common: shared contracts and codecs. Keep protocol framing and domain metadata independent of Swing, tracker sessions, and receiver filesystem policy. No new framework or runtime dependency.
  2. Tracker: presence only. One registration belongs to one live control connection. The tracker observes source IP, advertises peer listening ports, excludes the requester, and sorts display names. File bytes never traverse this connection. No durable registry or catalogue.
  3. Peer runtime: lifecycle and resource owner. Every peer is a tracker client, a peer server for incoming transfers, and a peer client for outgoing transfers. Runtime owns discovery, listener, transfer admission, and teardown.
  4. Transfer: sequential stop-and-wait. Preserve file offer/accept/reject, per-chunk SHA-256 and ACK, three total attempts on explicit RETRY, whole-file verification, and direct TCP. No downloader requests, resume, or multi-source scheduling in foundation.
  5. Storage: one temporary file per receive. No unverified bytes appear under a completed filename; existing files are not overwritten. Failed partials remain identifiable, are not resumable, and are never silently reused.
  6. Swing: presentation only. Configuration I/O, networking, hashing, and teardown do not block the EDT. TransferListener remains the presentation boundary, enabling headless testing without Swing windows.
  7. Documentation: plan → contract → implementation → evidence. Each work item has stable anchors, an implementation state, and separately recorded verification status.

F-02 — CREATE a repeatable build and behavioral proof gate

Configure a deterministic Maven reactor gate with committed behavior-focused tests on JDK 21.

  • Pin maven-compiler-plugin 3.13.0 (release 21), maven-surefire-plugin 3.5.2, and maven-failsafe-plugin 3.5.2.
  • Centrally manage org.junit.jupiter:junit-jupiter 5.11.4 in root POM; add with test scope to all three modules.
  • Add baseline tests for framing roundtrip, tracker registration/list/disconnect, transfer flows, and checksum comparison.
  • Expose public int localPort() on TrackerServer and PeerServer for ephemeral port binding.

F-03 — MODIFY input boundaries before any side effects (R-004, R-007)

Validate all wire and configuration inputs before memory allocation or state mutation.

  • Expose FrameIO.MAX_PAYLOAD_BYTES = 64 * 1024 * 1024. Add FrameIO.read(InputStream, int maxPayloadBytes).
  • Create TransferProtocol with DEFAULT_CHUNK_BYTES = 1048576 (1 MiB) and MAX_CHUNK_BYTES = 8388608 (8 MiB).
  • Create TrackerProtocol with MAX_ACTIVE_PEERS = 64 and MAX_PEER_LIST_PAYLOAD_BYTES = 1048576 (1 MiB).
  • Validate FileMetadata compact constructor: canonical UUID, nonblank fields, valid chunk calculations, 64-hex SHA-256.
  • Validate PeerInfo compact constructor: nonblank fields, max 255 code units, port 1..65535, reject ISO controls via Character.isISOControl.
  • Validate AppConfig.load: check raw identity values before trimming; enforce strict boolean parsing for transfer.autoAccept.
  • Validate tracker CLI port argument before binding.

F-05 — MODIFY sequential transfer state machine and accounting (R-004, R-005)

Enforce strict sequential invariants and truthful progress counters.

  • Validate source file is readable regular file before offering; fail on truncation or digest mismatch.
  • Match offered transferId on decision, ACKs, and verification reply. Match chunkIndex on ACK.
  • Enforce ACK statuses strictly: only OK and RETRY. Limit explicit sender hash retries to 3 total attempts.
  • Receiver checks chunk layout: chunkIndex == nextChunkIndex, expected offset, exact expected length, 64-hex chunk hash.
  • Duplicate handling: if chunkIndex == nextChunkIndex - 1, match previous layout and SHA-256; re-ACK OK without rewriting or incrementing.
  • Truthful progress accounting: keep confirmed counters outside try blocks; fix TransferUpdate.progressPercent() (100% for completed empty file, 0% for noncompleted empty file).

F-06 — REPLACE destination selection with owned staging and publication (R-001)

Replace exists-then-select with atomic hard-link publication on local NTFS/ext4.

  • In FileNameUtil: normalize slashes, strip path traversal, replace invalid characters with _, strip trailing spaces/dots, revalidate basename (reject empty/./..), prefix _ for Windows device names.
  • Retire uniqueDestination. Add createPartial(Path) using Files.createTempFile(directory, ".p2p-", ".part").
  • Check available space before sending FILE_ACCEPT; remove setLength preallocation.
  • Add publishVerified(Path part, Path directory, String fileName) using Files.createLink(candidate, part). Fallback with (n) on collision.
  • Retain verified .part on link failure or whole-file digest mismatch; never overwrite, copy, or silently discard.

F-04 — MODIFY discovery ownership and tracker resource lifetime (R-003, R-006)

Implement owned registrations, atomic snapshots, and bounded concurrency in the tracker.

  • Replace PeerRegistry.register with boolean register(PeerInfo) via putIfAbsent. Unregister via conditional removal.
  • Duplicate ID sends ERROR message="Peer ID already registered" and closes session.
  • Build atomic List<PeerInfo> snapshot per list request.
  • Use bounded ThreadPoolExecutor (max 64) with SynchronousQueue. Immediately close incoming sockets on saturation.
  • Apply 15,000 ms read timeout until registration completes; track all client sockets and cleanly close with 5-second shared deadline.

F-07 — MODIFY peer admission, phase waits, and desktop lifecycle (R-002, R-005, R-006)

Add timeouts, bounded transfer concurrency, shared monotonic shutdown, and EDT-safe lifecycle.

  • Add configuration properties: tracker.read.timeout.ms=15000, transfer.read.timeout.ms=15000, transfer.prompt.timeout.ms=120000, transfer.offer.response.timeout.ms=135000, transfer.verify.timeout.ms=300000, transfer.max.concurrent=4.
  • Enforce strict validation: transferOfferResponseTimeoutMillis > transferPromptTimeoutMillis.
  • Bounded transfer pool (max 4) with SynchronousQueue. Reject excess incoming/outgoing jobs promptly.
  • Package-private TransferSession tracking sockets, cancellation, and terminal states.
  • Two-phase teardown with single monotonic 5-second deadline (System.nanoTime() + 5s) shared across worker/acceptor waits.
  • IncomingFilePrompt.accept takes timeout; Swing dialog uses timer and background future; late click cannot accept after expiry.
  • Add CANCELLED status to TransferStatus for local cancellation.
  • EDT safety: load config and start runtime off EDT; MainFrame.setStarting(boolean) disables actions during startup; handle rejection cleanly.

F-08A — PROVE core foundation locally, then on the required VM topology

Deliver dual proof receipts for localhost and cross-machine deployment.

  • F-08A Local: Run core matrix via mvn -B -ntp clean verify, run throwaway PackagedPeerSmoke against produced shaded JARs, and verify real Swing application flow on Windows.
  • F-08A VM: Windows host (tracker) + 2 Ubuntu Desktop VMs (peers) over host-only network. Demonstrate registration, direct transfer, SHA-256 equality, rejection, restart, and tracker loss during transfer.

Gated future P2P features

The following features remain Planned on the roadmap. Their engineering entry gate requires F-01A–F-07 implementation and current F-08A local PASS with zero dependency-relevant defects:

  • Resumable transfers: Requires persisted transfer metadata (.part.meta), validated chunk state, and restart negotiation.
  • Shared-file catalogue & search: Content-addressed fileId advertising, tracker metadata indexing without payload relay.
  • Explicit chunk requests & multi-source download: Downloader-driven scheduling, chunk assignment, duplicate prevention, source failover.
  • Public / untrusted network transport: Cryptographic peer identity, TLS/authenticated framing; R-008 remains unresolved.

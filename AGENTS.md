# Project instructions

- Read `docs/index.html` and the relevant handbook pages before changing behavior.
- Every repository change, however small, must update all affected documentation in the same task.
- Add one entry to `docs/changelog.html` per completed change set, including documentation-only changes.
- Keep implemented, planned, known-limit, and unverified behavior clearly separated.
- Verify links, examples, diagrams, simulations, commands, and source claims affected by the change.
- Follow the full procedure and impact map in `docs/maintenance.html`.
- Do not commit, push, or deploy unless explicitly requested.

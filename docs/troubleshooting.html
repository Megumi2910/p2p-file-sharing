Symptom-first diagnosis

Find which boundary failed

Check process, route, port, and protocol in that order. Preserve console output and the exact UI message before restarting; the application has no persistent diagnostic history.

SymptomLikely cause and checksRecovery
Tracker does not startInvalid/non-numeric port, port already bound, firewall. Run netstat -ano | findstr :5000.Use a free port and match peer configuration.
Peer startup error or no windowMissing properties, invalid number, peer port conflict, tracker unreachable, or tracker accepted but did not respond.Validate config and network; end a stuck process because reads have no timeout.
Peer not listedList is manual, peer is not registered, duplicate ID replaced it, or tracker connection ended.Refresh; inspect registration logs; use unique IDs; restart affected peer.
Listed but cannot receiveAdvertised observed IP is unreachable from sender, peer port blocked, or listener stopped.Use nc -vz host port; fix VM routing/firewall and restart.
Waiting for acceptance foreverDialog is hidden, receiver task is blocked, or receiver stays connected but silent.Bring receiver window forward; if unresponsive, terminate and restart.
Transfer freezes during chunksRemote stopped responding without closing; no read timeout exists.Restart peers; retain/delete the partial file deliberately.

Hash mismatchMissing/overwritten ranges, concurrent collision, malicious metadata, or content changed during sending.Keep the .part for investigation or remove it; resend after stabilization.

Fast network ladder

  1. Can each VM see its own IP with ip a?
  2. Can each VM ping the Windows host-only IP?
  3. Is the tracker listening on Windows port 5000?
  4. Does each peer log a tracker-observed address?
  5. Can Alice open Bob’s peer port with netcat?
  6. Does refresh cause a tracker request and response?

Partial files

A .part file means publication did not finish. The application cannot resume it and does not automatically delete it. Before deletion, ensure no peer process is using it. Its allocated length may equal the advertised final size even when many ranges were never received because setLength preallocates it.

Do not infer integrity from size or 100% progress. Only a successful whole-file SHA-256 and final rename prove the current receiver accepted the completed content.

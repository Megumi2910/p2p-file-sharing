## Foundation contract

### Architecture to preserve

1. **`common`: shared contracts and codecs.** Keep protocol framing and domain metadata independent of Swing, tracker sessions, and receiver filesystem policy. No new framework or runtime dependency is needed.
2. **Tracker: presence only.** One registration belongs to one live control connection. The tracker observes source IP, advertises peer listening ports, excludes the requester, and sorts display names as today. File bytes never traverse this connection. No durable registry or catalogue is introduced.
3. **Peer runtime: lifecycle and resource owner.** It owns discovery, the listener, transfer admission, and close/rollback. Transfer tasks own individual file handles; the manager can close their sockets and interrupt their work.
4. **Transfer: sequential stop-and-wait.** Preserve file offer/accept/reject, per-chunk SHA-256 and ACK, three total attempts on explicit `RETRY`, whole-file verification, and direct TCP. Do not implement downloader requests, resume, or multi-source scheduling in the stabilization steps.
5. **Storage: one temporary file per receive.** No unverified bytes appear under a completed filename; existing files are not overwritten. Failed partials remain identifiable but are not resumable and are never silently reused.
6. **Swing: presentation only.** Configuration I/O, networking, hashing, and teardown do not block the EDT. `TransferListener` remains the presentation boundary, and headless integration tests use the same runtime without constructing Swing windows.
7. **Documentation: plan → contract → implementation → evidence.** Each work item has stable anchors, an implementation state, and separately recorded verification status. A proposed behavior is not changed to Current until its relevant implementation and proof exist.

Protocol v1 magic, version, field encoding (Java modified UTF), message codes, existing required header names, and successful current traffic are preserved. Malformed/ambiguous traffic previously accepted will be rejected; that compatibility tightening must be stated. Unknown additional headers remain tolerated. No fallback protocol, aliases, or parallel legacy transfer path is added.

### F-04 — MODIFY discovery ownership and tracker resource lifetime (R-003; tracker part of R-006)

- Replace `PeerRegistry.register(PeerInfo)` with `public boolean register(PeerInfo peer)`, implemented with `putIfAbsent`: first live registration wins; a duplicate ID is rejected rather than replacing the active value. Replace `unregister(String)` with `public void unregister(PeerInfo peer)` using conditional removal of the owned value. Do not retain an unconditional removal API.
- `TrackerServer.handleClient` retains its owned `PeerInfo` only after successful registration. Reject another registration on the same socket without changing its identity. Duplicate ID sends `ERROR` with `message="Peer ID already registered"` and closes the rejected session; repeated registration sends `message="Already registered"` and closes, releasing that session's original registration. A failed registration never owns or unregisters another entry. Both close/EOF and error paths release the owned entry exactly once.
- Build one `List<PeerInfo>` snapshot per list response; use its size for the count header and its content for encoding. Preserve existing exclusion and ordering.
- Replace the tracker cached pool with a `ThreadPoolExecutor` capped at **64** concurrent clients and a `SynchronousQueue` (no pending accepted-socket queue). On saturation/closing, immediately close the new socket; do not block the acceptor writing an overload response or run a handler on the acceptor thread. Catch rejection so admission pressure never kills the accept loop.
- Track accepted sockets from acceptance through handler completion, including submission failure. `close` prevents new admission, closes the listener and every tracked client, then interrupts and waits up to **5 seconds** for workers. Make close idempotent and exception-safe; one close failure cannot skip remaining resources. Remove sockets from tracking in finally. Serialize acceptance/registration with the closing flag sufficiently to prevent a socket being added after shutdown's final drain.
- Apply a **15,000 ms** read-inactivity timeout until registration completes. After successful registration, remove the read timeout: an idle registered peer is intentionally allowed to remain connected because the current UI refreshes manually and there is no heartbeat. This is not a claim that half-open connections are promptly detected; a dropped network without EOF remains a documented limitation until client activity/TCP failure/shutdown.
- For deterministic integration fixtures, expose `public int localPort()` on `TrackerServer` and `PeerServer`, valid after a successful bind. Permit port 0 through their internal server constructors for ephemeral binding in tests; production CLI/config validation still rejects 0. Log the actual bound tracker port and preserve the existing 5000 log when using the default. No public test-only startup protocol is added.

**Callers:** only `TrackerServer.handleClient` calls production registry mutation; `TrackerApplication` constructs the tracker. Tests adopt the ownership API. `PeerRuntime` continues constructing `PeerServer` with validated production ports.

**Documentation contract:** architecture/presence lifetime, protocol ERROR behavior, setup duplicate-ID guidance, troubleshooting, tests, and R-003/R-006. State that the resource cap bounds client slots, not authenticated users or attack resistance.

### F-05 — MODIFY the sequential transfer state machine and accounting (R-004/R-005)

- In `FileSender.run`, compute total chunks with the same overflow-safe quotient/remainder rule as `FileMetadata`. Validate the source is a readable regular file before offering it. If it becomes unreadable/truncated or transmitted bytes no longer match the offered digest, fail rather than report verified success; do not claim filesystem snapshot isolation or detection of arbitrary source changes outside the transmitted range. Hash each chunk once before its retry loop, reuse that hash and payload for all attempts, and count bytes only after a matching `OK` ACK.
- Require the accepted/rejected response, every ACK, and final verification result to match the offered `transferId`. ACK must also match the current `chunkIndex`. Only exact `OK` and `RETRY` are valid ACK statuses; unknown statuses are protocol failure, not implicit retry. Keep three total transmission attempts for explicit hash retry; do not add automatic reconnect or timeout retransmission. `VERIFY_RESULT` allows only `OK` or `MISMATCH`.
- In `FileReceiver.run`, validate each chunk before hashing/writing: matching transfer ID; `0 <= chunkIndex < totalChunks`; expected offset `chunkIndex * (long) chunkSize`; exact expected length `min(chunkSize, fileSize - expectedOffset)`; a 64-hex chunk digest; offset/file bounds checked by subtraction after validated multiplication. This prevents overflow rather than detecting it after a seek/write.
- Maintain `nextChunkIndex`, `receivedBytes`, and the last accepted chunk digest. New chunks must have `chunkIndex == nextChunkIndex`. A repeat of exactly `nextChunkIndex - 1` with identical validated digest/layout/content is re-ACKed `OK` without writing or adding bytes. A conflicting repeat, older duplicate, skipped/future index, wrong session, or invalid layout fails without modifying stored content or progress. This deliberately implements stop-and-wait idempotency with constant session memory, not arbitrary out-of-order scheduling or a file-size-dependent bitmap.
- A valid-layout new chunk with wrong payload hash receives `CHUNK_ACK status=RETRY` and changes no accepted state. `TRANSFER_COMPLETE` requires the accepted transfer ID, empty payload, `nextChunkIndex == totalChunks`, and `receivedBytes == fileSize`; early completion cannot invoke whole-file publication. Empty files use zero chunks and the normal verification exchange.
- Keep confirmed counters outside try blocks. Every failure update includes last confirmed bytes, phase, and a nonempty cause (fall back to the exception class name). Sender confirmed bytes mean matching ACKs; receiver confirmed bytes mean unique verified writes, so values may differ on lost acknowledgements. Never reset progress to zero on failure or mark whole-file verification successful merely because progress reaches 100%.
- Fix `TransferUpdate.progressPercent()` using overflow-safe calculation (bounded floating-point ratio is sufficient for an integer display): clamp malformed negative counts defensively, show completed empty files as **100%**, and other empty states as **0%**. Preserve the public record fields and six-column table contract; do not turn status/accounting work into a table architecture refactor.

**Documentation contract:** lifecycle, protocol matrix, concepts/idempotency, user-visible progress/errors, troubleshooting, and R-004/R-005. In `docs/assets/js/site.js`, retain the existing illustrative branches but make wording reflect implemented state only; the stall branch is not updated until F-07 actually provides timeouts.

### F-06 — REPLACE unsafe destination selection with owned staging and no-overwrite publication (R-001)

- Reuse `FileNameUtil` as the filename policy owner. `safeBaseName` must handle both slash styles independently of the receiver OS, strip directory components, reject empty/`.`/`..` results, and normalize characters forbidden on Windows (`<>:"/\\|?*` and controls) to `_`. Remove trailing spaces/dots and prefix `_` for Windows device basenames (`CON`, `PRN`, `AUX`, `NUL`, `COM1`–`COM9`, `LPT1`–`LPT9`, including names with extensions). Preserve ordinary Unicode names. Overlong/unsupported filesystem names fail clearly; do not silently truncate into collisions.
- Retire `uniqueDestination(Path,String)` and its exists-then-select contract. Add `public static Path createPartial(Path directory) throws IOException` using `Files.createTempFile(directory, ".p2p-", ".part")`; the random local name, not sender metadata or transfer ID, owns the path. Only call it after valid metadata and acceptance. Explicit rejection creates no transfer file.
- Open the created partial and verify the destination is usable before sending `FILE_ACCEPT`. Remove `RandomAccessFile.setLength(metadata.fileSize())`: the current sequential receiver grows the file through verified chunk writes and must not reserve an arbitrary advertised length before receiving bytes. Before accepting, reject when the declared size exceeds currently reported usable space, but document this as advisory rather than a disk quota/reservation guarantee; later I/O failure retains the partial.
- Add `public static Path publishVerified(Path part, Path directory, String fileName) throws IOException`. It is called only after successful whole-file verification and after closing the writer. Try the sanitized basename, then the existing `name (n).extension` convention. Atomically claim the final directory entry with `Files.createLink(candidate, part)`; on `FileAlreadyExistsException`, try the next suffix. This gives verified-content publication and no replacement even across concurrent processes; an existing symlink also counts as a collision.
- The staging and final path must be in the same download directory/filesystem.
